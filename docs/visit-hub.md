# Rental and facility visit paths

The existing Google rental offer links to `/visit`. The primary claim CTA still goes directly to the rental catalog with the existing session-saved offer. `/visit/rentals` explains the rental agreement path; `/visit/facility` links to participant waivers and tells party guests to use their booking-specific invitation link.

Staff use `/admin/visits`, linked from Google ad analytics, the Operations menu and the waiver desk. It requires the existing staff session before loading records. The date and contact search apply to one service tab at a time. Rental cards show the stored booking total, current agreement state and saved additional terms (including an applied Google offer). Facility cards link to the existing party records, while Open Play continues through the waiver desk. Load failures are distinct from empty results.

This page does not merge customer identities by name/email, expose customer records publicly, change Google campaign spend/destination, grant a facility discount, sign waivers, mark arrival, redeem a code or record payment. Existing operational desks remain responsible for their actions. Search results must be verified by staff.

The current GOOGLE15 code is shared and reusable. Unique email-linked vouchers, atomic reservation/redemption, cancellation release rules and customer identity verification remain a separate implementation; no UI may describe the current code as single-use. The Google analytics page states this limitation.
