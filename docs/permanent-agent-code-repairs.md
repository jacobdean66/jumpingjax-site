# Permanent Agent code repairs

The owner dashboard at `/admin/agents#code-repairs` accepts an everyday description, a website or dashboard page path and the text that should be visible after the fix. The conversational Permanent Agent can investigate source and prefill this request for review. Preparation does not queue a paid run; the owner starts it with **Prepare a code fix**. A dedicated durable queue keeps coding jobs separate from the website's short-lived diagnostic workers.

The GitHub workflow is scheduled every five minutes, but GitHub controls the actual start time and can delay queued runs. A recent heartbeat confirms a check-in; configured credentials alone do not establish that a worker is currently running. It uses the official Codex Action with its workspace permission profile and sudo removal. The API key is supplied only to that action's protected proxy. The coding job has read-only GitHub permissions and no production application credentials. The supervisor script is preserved outside the writable checkout. It checks allowed files, the original Git base, TypeScript, lint, original tests, including existing email/print, inventory and invitation regression suites when relevant. Public-page requests also require actual desktop/mobile browser behavior. Requests for `/admin`, `/api` or `/driver` application code produce reviewed engineering drafts: they run code checks without production credentials and explicitly require owner verification of the signed-in page, print output and business behavior before merge. Their browser check stays false; no automated visual success is claimed. Failed checks become one automatic correction prompt. Two coding attempts is the limit.

A separate publisher job applies the exact verified patch in a fresh checkout, checks its hash and opens a draft pull request. No application code executes in that job. The publisher cannot merge or deploy repairs. The dashboard only reports `review_ready` after receiving a changed commit, a repository PR and the checks required for the queued scope. The finish endpoint binds the result to the stored page path and active lease. Protected-page drafts display an additional **Owner preview required** warning, including in the PR. Worker completion text is not accepted as evidence. Failed or expired work stays failed; another paid run requires a new owner request.

## Activation

1. Apply only `supabase/migrations/20261022180000_create_agent_code_repairs.sql`, transactionally, and record that version in the migration ledger. Do not push unrelated historical migrations.
2. Generate a strong random worker token and save it as `CODE_REPAIR_RUNNER_TOKEN` in Vercel server environment variables and GitHub Actions encrypted secrets. Never place a token in source, browser configuration, logs, screenshots, artifacts or a prompt.
3. Store an owner-authorized OpenAI project key as the GitHub Actions encrypted secret `CODE_REPAIR_OPENAI_API_KEY`. The worker does not receive production Supabase, Vercel, customer, payment or platform credentials. API inference is billable; requests are limited to ten per day, three outstanding and one active worker, with two attempts each.
4. Enable the repository option allowing GitHub Actions to create pull requests. Keep the default workflow token permission read-only; only the separate publisher declares write permissions.
5. Merge the verified integration, deploy the application, and manually run **Permanent Agent code repairs** once. An empty queue only records a worker heartbeat. Confirm the dashboard shows a recent worker connection.
6. Queue one harmless public-page repair, require a real code change and desktop/mobile screenshots, and check the draft PR and dashboard result. Also prove rejection/correction before declaring unattended repairs accepted.

## Controls and limits

Owner endpoints require the existing owner session and same-origin JSON mutation guard. The worker endpoint accepts only the dedicated bearer token and never exposes customer data. Worker requests also need a matching, unexpired per-task lease. Coding or supervisor pause and emergency stop prevent claims and invalidate lease checks. Cancellation is permanent. An already executing model call can finish, but further coding attempts and publication check the controls again.

The public-page scope supports small UI and pure application code repairs, including home-page changes and new public pages. The reviewed application scope also covers dashboard pages, API handlers, invitation-builder source and print code. Both exclude tests, dependencies, workflows, agent controls, authentication, security and legal waiver source. No coding task changes live business records or deploys its patch. Public pages are previewed without production secrets; outbound browser requests are blocked. HTTP health is not a root-cause or visual test.

The conversational agent has bounded, read-only deployed repository, route, public HTML, operational database and Office Inbox tools. It cites checked sources and reports failed or limited lookups. A separate `prepare_catalog_item` tool opens a new-item draft in Inventory: supplied title, category, wording and price are editable; an unknown price remains blank, the owner adds a photo and reviews visibility before saving. The tool does not save or publish an item. Existing-item edits ignore new-item drafts. Invitation wording/layout/artwork correction requests retain their existing specialist preview-and-approval flow.

GitHub scheduled runs can be delayed. A missing worker heartbeat is displayed separately from configured credentials. A cancelled lease prevents the final acceptance callback; there is no distributed transaction spanning GitHub and Supabase, so cancellation during the final PR API request can leave an unaccepted draft PR. Nothing automatically merges it.

## Verification

Run `pnpm exec tsc --noEmit`, focused ESLint, the agent-manager and network tests, `node --import tsx --test src/lib/agent-manager/code-repair.test.mts`, and `node --test scripts/code-repairs/verify.test.mjs`. The SQL tests use isolated PostgreSQL via PGlite and exercise the actual migration, roles, controls, restart, lease recovery and queue budgets. They do not contact production or invoke a model. Verifier regressions prove incomplete public work is rejected and a corrected public candidate must pass an independent browser check. Protected-page tests prove that code checks can produce a draft with browser=false and mandatory owner preview; the same evidence cannot satisfy a public-page request. Form rendering tests verify draft fields, unknown price, existing-item isolation and unpublished status. A live Codex/GitHub/browser acceptance run is a separate activation requirement.
